# 下一阶段：让 LLM 自主编排（边界 · 接口 · 判定）

> 本文回答三个问题：哪些环节可以自动化、哪些必须人工、以及"铺路"具体铺了什么。
> 文末附一次真实的"模型生成 → 校验判死"实测。

## 一、一条判据

> 一个环节能不能交给 LLM，只取决于：**它"做对了"能不能被代码判定**。
> 能判定 → 可以下放，判定器兜底；不能判定 → 下放只是把不可验证的判断换成另一个不可验证的判断。

推论：**人工的工作不是"写编排"，而是"生产判定器"。** 下一阶段人工不会消失，只是从前台（手写 FlowConfig）退到后台（写判据与阈值）。

## 二、编排动作一共 8 个

| # | 动作 | 可判定？ | 本任务 | 下阶段 |
|---|---|---|---|---|
| A1 | 分诊：这题需要几步、走哪类策略 | 中（看结果） | 人 100% | LLM 首判 + 人抽检 |
| A2 | 拆解：拆几个子任务、职责边界 | ✔ 校验器 + 空跑 | 人 | LLM |
| A3 | 接线：routes、嵌套层数 | ✔ 8 条规则 | 人 | LLM |
| A4 | 选型：交给哪个 codeId | ✔ 存在性 + 签名匹配 | 人 | LLM 查 manifest |
| A5 | 数据契约：params/results | ✔ 数据流闭合 | 人 | LLM |
| A6 | 参数：块大小、top-k、批量、重试 | ✔ 预算与阈值 | 人拍 | LLM 提议 + 消融定值 |
| A7 | 失败处理：重试/降级/放弃 | ✔ 预算内 | 人写死 | 预算内自主 |
| A8 | **取舍：这结构值不值得留、还要不要投** | ✘ | 人 | **人** |

**8 项里 7 项可下放，1 项本质保留。**

## 三、人工的两种性质（这是"为什么"的核心）

| 类型 | 覆盖 | 原因 | 会消失吗 |
|---|---|---|---|
| **暂时性人工** | A1–A7 | **缺判据，不是缺能力**。人在充当 validator / reward | 会。判定器建齐即退化为"受控自动" |
| **本质性人工** | A8 | 输入是**人的效用函数**（预算、时间、值不值），不是数据 | 不会 |

问"哪些必须人工"之前，先问"是还缺判据，还是根本没有判据"。前者是工程进度，后者是目标定义。

## 四、三个轴 → 可计算的级别

| 字段 | 含义 | 推导 |
|---|---|---|
| `deterministic` | 同输入同输出，不调模型 | `true` → **L0 纯自动** |
| `verifiable` | 输出能被代码判死 | 非确定 + `true` → **L1 受控自动** |
| 两者皆假 | 无客观对错标准 | **L2 人工保留** |

本任务的实测落位：

| 环节 | 级别 | 依据 |
|---|---|---|
| 取样本 / 切块 / 候选召回 / 判分 / 校验 | L0 | `dataset.ts` `chunk.ts` `retrieve.ts` `score.ts` `validate.ts`，删掉模型也能跑 |
| 契约生成 / 精读 / 核验 | L1 | 格式与证据可校验，模型可跑 |
| 结构组合（A2–A5） | L1 | 8 条规则可判死（见 §六实测） |
| 取舍（A8）、判分口径、发布 | L2 | 目标函数未形式化 |

## 五、"铺路"铺的是什么：一次受约束的搜索

| 搜索要素 | 对应物 | 状态 |
|---|---|---|
| 动作空间 | `src/orchestrator/manifest.ts`（codeId + 签名 + 三轴） | ✅ 已实现 |
| 合法性约束 | `validate.ts` 8 条规则（含数据流闭合） | ✅ 已实现，7/7 破坏可捕获 |
| 反馈信号 | `trace`（逐节点）+ `score.ts`（strictPass/规范化） | ✅ 已实现 |
| 代价约束 | `Budget`（callsMax/tokensMax 已写进 manifest 的 costHint） | ⚠️ 声明了，尚未强制执行 |
| 人工介入度量 | `meta.authoredBy` / `meta.humanTouched` | ⚠️ 字段已写入配置，尚未进报表 |

LLM 生成 FlowConfig = 在这个空间里搜一个解：L1 低成本否掉非法结构，L2/L3 才花钱。

## 六、实测：模型生成 → 校验判死

`pnpm orchestrate --autogen-demo`（1 次模型调用）：

**输入**：manifest 摘要（3 个节点的 codeId、入参、出参、说明）+ 场景（长文问答，答案是唯一字符串）。

**模型输出**：一个三节点平铺流程 `plan → read → verify`，节点 reference 全部合法。

**L1 校验结果**：

```
[WARN][R6] plan   节点归属 orchestration.main，被放进了 orchestration.auto
[WARN][R6] read   节点归属 orchestration.read，被放进了 orchestration.auto
[WARN][R6] verify 节点归属 orchestration.verify，被放进了 orchestration.auto
[ERROR][R7] read  需要入参 traceId，但没有任何上游产出它（会被静默裁成 undefined）
[ERROR][R7] read  需要入参 stopAfterRead，但没有任何上游产出它（会被静默裁成 undefined）
[WARN][META] 缺少 meta.authoredBy，无法统计人工介入率
结论：判死（存在 error）
```

**这个结果比"生成成功"更有价值**：模型给出的结构**看起来完全合理**（三个节点、路由完整），但漏了 `traceId`/`stopAfterRead` 两个入参——如果直接跑，引擎会静默把它们裁成 `undefined`，`code.read` 里 `if (!input.traceId) throw` 会立刻报错，而人只会看到"节点失败"，不知道是结构问题。

校验器在**零成本、零执行**的情况下判死了它。这就是 L1 的意义。

**局限（必须说清）**：
- 只验证了 L1（静态合法），没跑 L2（空跑可执行），因为生成的结构本身不合法；
- 模型没有选择嵌套（把 read/verify 平铺成 event 节点），校验器不会因此判死——"该不该嵌套"仍是 A2 的判断题，属于 L2 人工或更强的判据；
- 一次样本，不能说明生成成功率。

## 七、生成器的设计（要给它什么 / 约束什么 / 怎么判）

**输入**
1. `manifest.ts`：可用的 codeId、入参、出参、三轴、costHint；
2. 任务画像：题型（锚点/计数/情节/代码）、context 规模、预算上限；
3. 反例：`docs/FAILURES.md` 的四类失败机制（告诉它哪些结构注定失败）。

**约束（硬）**
- reference 必须在 manifest 内；
- 每条路由端点合法、节点单入边、无环、层数 ≤3；
- params/results 必须闭合（R7）；
- 预算：节点 costHint 之和 ≤ 上限；
- 必须填 `meta.authoredBy='llm'`，人改过的字段进 `humanTouched`。

**判定（三道）**
| 层 | 判什么 | 成本 | 现状 |
|---|---|---|---|
| L1 | 8 条静态规则 | 0 | ✅ 已可跑 |
| L2 | 桩函数空跑，验证参数传递与 results 裁剪 | 0 | ⚠️ 骨架在（`--smoke-nest`），但跑的是真节点；要做成零成本闸门需补 stub 注册表 |
| L3 | 真实跑 + 指标 + 契约 | 3–4 次/条 | ✅ `--all` 已可跑 |

## 八、人工介入率（可度量的"必须人工"）

```
人工介入率 = 人改过的编排字段数 / 编排字段总数
```

配置里已有 `meta.humanTouched`（本任务四个流程都是 `['nodes','routes','params','results']`，即 100%）。下一阶段目标：

| 版本 | 结构来源 | 人工介入率 |
|---|---|---|
| V3（本任务） | 人写 | 100% |
| V-autogen | LLM 生成 | < 20%（人只改 A6 阈值、A8 取舍） |

## 九、这条要求达标没有：三个可验证检查

1. **把 LLM 全摘掉**：`--check-issues` / `--validate` / `--plan-report` 全部可跑（0 调用）→ ✅
2. **让 LLM 自由生成**：校验器能判死 → ✅ 见 §六
3. **人工介入率可复算**：`meta.humanTouched` 可从配置反推 100% → ✅ 字段已在，尚未做成报表

## 十、结论

**铺路铺到"能判死",还没到"能生成对的"。** 这是这一阶段的真实位置：
- 动作空间、约束、反馈、代价四件套里，前三件已落地且实测有效；
- 生成器本体没做，只做了一次演示，证明"模型会给出看起来合理但静默失败的结构，而校验器抓得住"；
- 下一步不是让模型直接生成生产结构，而是让它生成候选、由 L1/L2 过滤、人只审通过的那几个。
